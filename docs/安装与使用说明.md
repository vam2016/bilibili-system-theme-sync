# B站系统主题同步（全站增强版）

版本：1.0.0 · 2026-10-03 · Chrome + Tampermonkey

## 安装

1. 在 Chrome 中安装或启用 [Tampermonkey（篡改猴）](https://www.tampermonkey.net/)。
2. 停用原来的「Bilibili主题色自动切换」以及其他 B 站主题脚本。如果使用 Dark Reader 扩展，请在扩展中将 B 站排除，避免两个主题引擎同时工作。
3. 打开本次提供的 `bilibili-system-theme.user.js`，复制全部内容。
4. 点击油猴图标 →「添加新脚本」（也可在管理面板点击加号），删除编辑器中的默认内容，粘贴刚复制的完整脚本。
5. 按 **⌘S** 保存，确认脚本已启用，然后刷新已经打开的 B 站页面。
6. 在 macOS「系统设置 → 外观」中选择深色或浅色。默认「跟随系统」会实时响应，无需再次刷新；选择 macOS 的「自动」外观也能响应系统发生的实际切换。

若 Chrome 提示脚本无法执行，打开 `chrome://extensions` → Tampermonkey → 详情，启用「允许用户脚本 / Allow User Scripts」。较旧的 Chrome 没有此开关时，可启用扩展页的「开发者模式」。依据：[Tampermonkey 官方说明](https://www.tampermonkey.net/faq.php#Q209)。

## 功能与覆盖

- 匹配 `https://bilibili.com/*` 和 `https://*.bilibili.com/*`，包括首页、视频、分类、搜索、动态、个人空间、直播首页及直播间。匹配的 B 站子框架也会运行脚本。
- 使用 Chrome 的 `prefers-color-scheme` 事件监听 macOS 外观变化，支持切回浅色；回到标签页或恢复页面时会再次确认当前状态。
- 动态分析页面样式，处理新增卡片、延迟加载内容及可访问的开放式 Shadow DOM 评论组件。
- 使用独立的动态配色引擎，视频、Canvas 和普通图片不加颜色滤镜；保留彩色弹幕的内联颜色和二维码的白色背景。
- 深色时移除直播间装饰皮肤背景，避免浅色大背景继续刺眼；浅色时恢复网站原有样式。
- 固定版本 Dark Reader 4.9.120 已打包进单个脚本，无外部 `@require`。安装后无需额外安装 Dark Reader 扩展。

## 菜单

在 B 站页面点击油猴图标，可以选择：

| 菜单 | 效果 |
| --- | --- |
| B站主题 · 跟随系统 | 默认设置，按系统深浅色实时切换 |
| B站主题 · 始终深色 | 无论系统外观如何，保持深色 |
| B站主题 · 始终浅色 | 保持浅色 |
| B站主题 · 暂停脚本 | 撤掉本脚本的深色效果 |
| B站主题 · 查看状态／排查问题 | 显示 Chrome 感知的系统主题、当前模式和引擎状态 |

模式保存在油猴中，并通过油猴设置变更监听同步到其他已打开的匹配页面。以上菜单出现在顶层页面，不重复添加到子框架。

## 实现与权限

旧脚本设置 `bili_dark` 和 `theme_style`，但依赖 B 站各页面本身是否提供原生深色样式，因此不同子站的表现不一致。[旧脚本源码](https://greasyfork.org/zh-CN/scripts/554740-bilidyntheme/code)。

本脚本使用 [Dark Reader 官方 API](https://github.com/darkreader/darkreader#using-dark-reader-on-a-website) 的动态配色功能。为了避免原生深色与动态配色叠加，本脚本将 B 站的原生 `theme_style` 偏好设置为 `light`，并移除根节点的 `bili_dark`；深色效果由本脚本生成。暂停或卸载后，这个原生偏好仍为浅色，可在 B 站重新手动选择。

`GM_xmlhttpRequest` 仅用于匿名读取 B 站公共 CSS，允许的域是 `bilibili.com`、`hdslb.com`、`biliimg.com` 及其子域，代码同时检查 HTTPS 和 `.css` 路径。不需要账号权限，不上传浏览记录，不调用登录、发弹幕或其他写入接口。资源本身的联网加载仍取决于 B 站及 CDN 的可用性。

内置 Dark Reader 使用 MIT 许可，完整许可见 `vendor/LICENSE`，也包含在脚本中。本版本补充了一个清理修正：关闭引擎时同时移除 Shadow DOM 内的反色样式。

## 已验证的范围

在 macOS 上用独立 Chrome 测试环境，向真实页面注入完整脚本，模拟油猴的 GM 接口，并用浏览器的主题模拟触发深浅色事件。未操作你现有的 Chrome 个人资料，也未在你的油猴中自动安装。

真实页面：B 站首页、动画分类、搜索、视频播放页、个人空间、动态首页、直播首页和一个正在直播的直播间，均完成深色 → 浅色切换与主文档样式撤销检查，并检查页面截图。

专用测试页面：实时切换、重复切换、手动模式、暂停、异步列表、页面内导航、先出现和后出现的开放式 Shadow DOM、浅色时样式清理、图片／视频／Canvas 无滤镜、彩色弹幕颜色保留、二维码白底、原生主题标记重写。另在 Chrome 隔离运行环境验证主题事件、GM 设置变更回调与后加载的 Shadow DOM。

这些验证不等同于遍历全站所有页面与所有登录状态。测试使用浏览器主题模拟，安装后请实际切换一次 macOS 外观确认系统联动。B 站以后更换结构、第三方 iframe、封闭式 Shadow DOM 和个别活动皮肤可能需要追加适配；第三方验证码可能保留浅色。实际直播间的部分推荐浮层尚未充分验证。

## 排查

- **所有页面都无变化**：检查脚本开关、匹配权限以及 Chrome 的「允许用户脚本」。安装后需刷新已打开页面。
- **系统深色但页面仍浅色**：打开「查看状态」。如果显示 Chrome 感知为浅色，关闭开发者工具 Rendering 面板中的 `prefers-color-scheme` 模拟，检查 Chrome 是否被强制使用某种颜色方案，再回到 B 站标签页。
- **系统切换没有响应**：确认油猴菜单选择了「跟随系统」，而不是「始终深色／浅色」或「暂停」。
- **颜色叠加或忽明忽暗**：停用旧脚本，并在其他深色扩展中排除 B 站后刷新。
- **少数区域仍然浅色或文字看不清**：记录完整页面网址、出现问题的区域及状态菜单内容，可据此继续补充针对性样式。

修改配色时，可在脚本末尾找到 `const theme = {`，调整 `darkSchemeBackgroundColor` 和 `darkSchemeTextColor`，保存后刷新即可。
